# 腕部手眼、基座定位与固定相机外参标定

## 三步网页流程

网页现在覆盖完整流程：

1. 固定标定板，使用腕部 RealSense A 和机械臂 TCP 位姿采集 25–35 组，求得 `T_tcp_camera`。
2. 求解时同时将 OpenCV 的标定板角点原点换算到**标定板几何中心**，输出 `T_base_board_center`、`T_board_center_base` 和基座原点在板中心坐标系中的 XYZ。
3. 将板移动到固定相机可见处后，旧板位姿必须作废。保持板不动，先用已标定的腕部相机和当前 TCP 单张重新定位板，再切换到固定相机拍一张，得到 `T_base_fixed_camera`。

步骤 3 不能在“移动板后只拍固定相机一张”的条件下直接完成，因为移动会破坏步骤 2 建立的板—基座关系。网页因此明确加入腕部相机重新定位动作；重新定位后至固定相机拍摄完成前不得移动标定板。固定相机默认序列号为 `148522072685`，也可在网页修改；其彩色相机内参从实际 1920×1080 流读取。

固定相机结果保存在当前 session 的 `fixed_camera_时间戳/result.json`，原图和检测预览与结果放在同一目录。`T_A_B` 始终表示把 B 坐标转换到 A 坐标，平移单位米；网页位置显示单位毫米。

## 基座位姿输出（GUI 20260914.3）

最终主结果为相机在机械臂物理基座中的位姿：`T_base_camera`、`camera_position_in_base_mm`、`camera_quaternion_xyzw_in_base`。它对应**最后一组有效照片拍摄时**的机械臂姿态，页面及 JSON 提供照片编号和时间；它不是实时位姿，移动机械臂后会改变。每组样本另含自己的 `T_base_camera`。

换算为 `T_base_camera = T_base_tcp @ T_tcp_camera`。`T_tcp_camera` 保留为固定手眼标定关系，不能用基座位姿替代它去计算其他机器人姿态。当前数据的 world offset 为零；若偏移非零或缺失，本版本拒绝把参考坐标冒充物理基座，显示基座结果不可用。坐标转换不会改善或隐藏原有标定误差，`needs_review` 结果仍然需要复查。


## 推荐：引导式 GUI

GUI 运行在远程主机，相机画面通过 SSH 隧道显示在本机浏览器，不使用本机摄像头。

远程终端启动（保持运行；若提示 GUI 已运行，使用现有服务即可）：

```bash
cd /home/wsx/code/codex_real2sim_capture/handeye
bash gui.sh
```

本机 Windows 新开 PowerShell，建立转发并按提示输入 SSH 密码（保持窗口运行）：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18765:127.0.0.1:8765 wsx@100.64.0.119
```

本机浏览器打开 http://127.0.0.1:18765 。在远程主机桌面使用时可直接打开 http://127.0.0.1:8765 。服务只监听回环地址，不对外网开放。

1. 点击“开启相机预览”：实时画面标注角点与坐标轴，并显示角点数、重投影误差。画面约每 0.35 秒更新；超过 3 秒未更新会遮罩提示，避免把旧帧误当实时画面。
2. 填入机械臂 IP，点击“连接机械臂”。连接失败仍可看相机；拍照保存必须连接机械臂。原项目的 192.168.1.245 曾连接失败，请核对当前网络及实际地址。
3. 填写本次标定名称和尺量的单格尺寸，确认板固定，点击“开始 / 继续本次标定”。不同设置不能追加到同一旧标定。
4. 按向导提示手动改变腕部位置和倾斜，停稳后点“已停稳，拍摄这一组”。等待保存提示后再动。页面显示有效组数、未通过原因；可单独弃用某组，原始图片保留。
5. 至少 15 组、建议 25–35 组后，点“计算腕部手眼与基座位置”。页面同时显示腕部结果及板中心坐标系下的基座位置。
6. 若移动标定板，点“我已移动标定板，作废旧位置”。可先切固定相机预览来摆板，再切回腕部相机，移动机械臂使板入镜，点击“定位当前标定板”。
7. 在板不再移动的前提下切换到固定相机，拍摄一张并计算 `T_base_fixed_camera`，下载固定相机外参 JSON。
8. 完成后点击“全部完成，释放设备”。关闭网页本身不会停止服务器或释放相机。

GUI 依赖远程现有 Flask，无需安装新依赖。界面没有机械臂运动按钮；所有相机和机器人操作由同一个工作线程串行处理，连续点击不会重复采集。

适用场景：标定板固定不动，RealSense A 刚性安装在腕部，人工改变机械臂位姿，每次停稳后采集。脚本只读取机械臂，不设置模式、使能、TCP、世界坐标偏移，也不发送运动指令。

## 调用（在远程 wsx 终端执行）

```bash
cd /home/wsx/code/codex_real2sim_capture/handeye
bash run.sh list-cameras
bash run.sh collect --config config.json --session sessions/wrist_A_01
```

启动后输入尺量的实际格长（单位 mm）。也可通过 `--square-mm` 提供实测数值。原 session 只能用同样的相机、内参、板尺寸和坐标配置续采；更改配置后用新目录。

- 人工移动机械臂，停稳至少约 2 秒，回车拍一组。拍摄完成前不要动机械臂或板。
- 每组会刷新 45 帧，采集前后及中间多次读取机械臂。位移超过 0.3 mm 或转角超过 0.15°会拒绝该组；这些是软件采样检查，不是硬件同步保证。
- 成功组保存原始 image.png、preview.jpg、角点、PnP 位姿、相机时间戳、机械臂多次读数。失败组保留原因，标定时跳过。
- `d` 将本次运行的上一组弃用，保留原文件；`q` 结束并释放设备。
- 不依赖桌面窗口，SSH 也可使用；在远程桌面打开各组 preview.jpg 检查标定板和坐标轴。

建议采集 25–35 组；脚本最低要求 15 组通过检测。覆盖不同位置、距离、左右倾斜和前后俯仰，确保绕至少两个不同轴有明显转动。不要只平移或只绕同一轴转。尽量让整板可见，避免模糊、反光、遮挡和近乎正对导致的平面位姿歧义。每组要求至少 10 个角点和 ≤1 px 重投影 RMS。

## 求解

```bash
cd /home/wsx/code/codex_real2sim_capture/handeye
bash run.sh solve --session sessions/wrist_A_01
```

求解只读已有图片和机械臂记录，不连接硬件。重新检测原图，过滤失败/弃用组，检查旋转多样性，比较 PARK/HORAUD/TSAI。约四分之一数据留作验证，不参与初始拟合和方法选择，最后用全量有效数据给出变换。

生成 sessions/wrist_A_01/result_时间戳.json，打印位置、四元数、验证误差。每次结果另存，不覆盖旧结果。

- `T_tcp_camera`：把相机 RGB 光学坐标转换到**当前活动 TCP 坐标系**，4×4 矩阵，平移单位米。
- `camera_position_in_tcp_mm`：相机光心在 TCP 坐标系中的位置，单位毫米。
- `camera_quaternion_xyzw_in_tcp`：相机朝向，四元数顺序 x,y,z,w。
- `T_camera_tcp`：上述变换的逆。
- `T_reference_board`：固定板在机械臂报告的参考坐标系中的估计位姿。
- 每组 `T_reference_camera`：该姿态下相机在机器人参考坐标系中的位姿。
- 关系：`T_reference_camera = T_reference_tcp @ T_tcp_camera`。

**TCP 不等于法兰**：已有记录存在 172 mm 工具偏移；本脚本不把偏移清零。若要相对法兰的变换，需再用经确认的 `T_flange_tcp @ T_tcp_camera` 转换。`reference` 是机器人接口实际报告的参考系；world offset 非零时不要误称原始基座系。配置及读数均保存在结果内。

一致性标准：固定标定板在各组计算出的位姿，留出验证和全量最大偏差均 ≤5 mm、≤2°，才标为 `consistency_passed`。否则保存 `needs_review`，退出码 2。数据不足或退化退出码 1。这些默认阈值是筛选标准，不是相机绝对精度认证；根据应用目标审查误差和图片，并使用新姿态独立验证。系统误差（板尺寸、内参、机器人模型、装夹变形等）不能靠一致性指标完全排除。

## 离线测试

测试随仓库测试套件放在 `tests/`，不再放在本目录：

```bash
PY=external/Data-MechanicSim/.venv/bin/python
"$PY" -m pytest tests/test_handeye.py tests/test_gui.py
```

依赖见根 README 的可选依赖组：算法需要 `calibration`（opencv），网页和 RealSense 采集需要 `handeye`（flask、pyrealsense2）。

`test_handeye.py` 涵盖已知真值的变换方向、噪声、单轴退化、静止检查、合成 ChArUco 图像以及完整文件求解流程；`test_gui.py` 用假相机与打桩的检测/读臂覆盖 HTTP 守卫、会话状态和两段式固定相机流程。两组都不连接相机，不移动机器人。

算法参考：https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html （calibrateHandEye，eye-in-hand）。
