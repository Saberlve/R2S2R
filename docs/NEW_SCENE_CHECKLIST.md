# 新场景交接清单

- [ ] scene_id、现场日期、采集设备/原生分辨率/序列号、数据与场景是否同一布置。
- [ ] Raw目录和校验清单；图像是否裁剪/翻转/校正，有无自动白平衡过渡。
- [ ] 世界坐标原点/轴、桌面尺寸、墙/门/邻桌测量端点与误差。
- [ ] 每个主要实体独立资产、尺度、原点、封闭性、碰撞需求与排除列表。
- [ ] 相机K/D、pixel_ops、profile hash、外参来源和独立验证结果。
- [ ] 模型机器人型号/轴数、控制器校准、TCP、world offset、采集期间是否变化。
- [ ] 每个动态mesh与相机的body绑定；夹爪leader/mimic、开口与命令语义。
- [ ] 几何先冻结，再做外观；同一固定mask及独立检查帧。
- [ ] 视觉baseline哈希、渲染模板与外观参数，禁止重复烘入倍率。
- [ ] 原始关节与action、时间戳、视频索引；转换前后数据量/索引一致。
- [ ] 物体位置/朝向、尺寸、质量、摩擦与置信度；估计值不充当独立真值。
- [ ] FK、EEF控制、抓取保持、穿透、滑移、力、扰动分开验收。
- [ ] 图像分辨率与渲染采样率、物理时间步明确；同一状态驱动所有相机。
- [ ] dry-run导出检查与待解决项；真实执行另行批准和现场验证。

先完成不依赖未知项的阶段。缺少可靠相机标定时仍可做机器人内部FK验证，但不能从图像准确定位物体；缺少物体参数时仍可跑示例抓取，但不宣称真实接触已辨识。


## 本项目最关键的两项，迁移时不要遗漏

- [ ] 如果有3D Scanner包，按SCANNER_BACKGROUND.md保留原图集与UV，独立注册扫描；分别处理规则门墙和有褶皱绿布，不直接把整个房间scan作为碰撞体。
- [ ] 如果次要相机K不可靠，按AZURE_CAMERA_ALIGNMENT.md固定可信相机、桌子和机器人，允许目标相机焦距+六维位姿联合拟合；保留原生像素、留出点、正深度约束和完整渲染检查。
