# 本次实践：保留什么，舍弃什么

## 作为主流程保留

- 已知桌面尺寸与明确测量端点作为几何约束；先求相对布局再细化资产。
- 独立语义Object/Collection、封闭规则几何、合理遮挡补全和Apply Scale。
- 固定相机原始RGB作为外观目标；手机照片用于几何/纹理细节，不能直接混合曝光和不同时间日光。
- 相机连接后至少等待10秒，同时记录曝光/白平衡；等待时间并不证明曝光已经稳定，应检查连续帧。
- 核实原生640×480与1920缩放裁剪的区别；所有pixel操作记录并参与profile hash。
- 先固定可信B相机、桌子、机器人，再处理Azure；不让次要相机补偿机器人姿态错误。
- iPhone LiDAR用于背景尺度、轮廓和可见结构参考；扫描清理后做背景资产，不把杂物粘进任务实体。
- 逐候选完整渲染、固定区域loss、多视角核对；geometry/camera与appearance分阶段优化。
- 相机与连接件刚性绑定到腕部关节；渲染由Newton状态驱动，所有视角共享同一状态。
- 记录TCP、world offset、标定joint origins与源码版本；observation与action分别转换。
- 当前Newton已有mimic约束时，只驱动夹爪leader。
- 原始文件和冻结baseline做hash核对；每次实验使用新目录。

## 条件成立时才使用

- 相机位姿图像搜索：仅在内参/尺度可信、对象姿态已固定时有意义；未知Azure内参只能标image_fitted。
- 投影颜色/纹理校正：可能吸收照明，不是真实反照率测量；新视角/新光照要重新验收。
- 从闭合TCP估计物体位置：可用于开发示例，但不能用于独立评估同一真实抓取轨迹。本repo已移除该自动推断。
- 灯光线性基：只适用于相机响应与相关渲染条件固定的近似搜索；完整Cycles复核的loss必须另报。
- 单视角像素loss：只表示该mask/该时刻的图像拟合，不能证明几何与接触正确。

## 不进入通用默认流程

- 无约束同时调相机、机器人底座、关节和背景。
- 用模型缩放或挪桌子抵消相机内参/裁剪错误。
- 将整个扫描作为一个物理mesh；恢复此前明确排除的线缆/装置。
- 用包含机器人/阴影的照片屏幕贴片冒充背景几何。
- SDK的TCP172mm与旧工程grasp offset140mm混用。
- 把目标关节当实测关节，把命令回填夹爪当传感器测量。
- 用附着、瞬移、固定约束或厘米级穿透支撑“抓取成功”。
- 把状态传输的72帧运动学视频当成真实动力学验证。

## 实验记录的真实结论

EEFAlignmentV1：38段、16133帧；控制器与本地FK的200个样本最大0.350mm/0.0102度；Newton FK内部一致性最大0.000877mm/0.000055度。这是数值链路一致性，不等于现实空间外参达到该精度。

调整arm kp2500→3500后，无物体EEF动力学跟踪从30/38提高到38/38满足P95≤5mm/1度；episode0用于开发，不计独立留出。生成抓取可抬升约10cm并保持2秒；hydroelastic穿透约1.39mm。

真实回放native有5/38达到抬升保持，但加入≤2mm穿透门槛后0/38通过。episode13的hydroelastic检查降低了穿透但没有夹起物体。故本仓库没有宣称真实抓取已经可靠复现，也没有辨识出真实夹爪力和摩擦参数。
